# SignalScope - цифровой осциллограф и анализатор сигналов

SignalScope -  проект по цифровой обработке сигналов, построенный вокруг Arduino Uno на ATmega328P и Python-части на ПК. Основная цель проекта - показать, как сигнал из физической среды проходит через ADC, таймерную дискретизацию, буферизацию, UART, бинарный протокол, затем обрабатывается в Python с помощью теории цифровой обработки сигналов (ЦОС): дискретное преобразование Фурье, фильтрация, оконные функции, оценка частоты, анализ алиасинга и сравнение с теорией Котельникова–Шеннона.

## 1. ЦОС, а не Arduino

Подход к проекту основан на ЦОС:

- Любой непрерывный сигнал x(t) мы можем представить в дискретный вид x[n] = x(nTs).
- Частота дискретизации Fs = 1 / Ts задаёт максимальную частоту, которую можно корректно восстановить без искажений.
- Теорема Котельникова–Шеннона: если fmax < Fs/2, то сигнал может быть восстановлен из отсчётов без потери информации.
- Если f > Fs/2, то в спектре возникает aliasing: высокий частотный компонент отражается в низкочастотную область.

 на каждом шаге видно:

- сигнал в аналоговой природе,
- его выборку по времени,
- количественную оценку частотного диапазона,
- влияние теоремы выборки,
- разницу между корректной дискретизацией и алиасингом.

Практически это означает, что основное ядро проекта будет опираться именно на:

- дискретизацию и аналого-цифровое преобразование;
- DFT/FFT;
- цифровые фильтры (FIR, moving average, cutoff);
- спектральный анализ;
- оценку частоты по временным и частотным методам;
- явление aliasing;
- окно Ханна и другие оконные функции.

## 2. Математическая основа проекта

### 2.1 Дискретизация сигнала

Пусть x(t) - непрерывный сигнал. После дискретизации получаем:

x[n] = x(nTs), n = 0, 1, 2, ...

где Ts = 1 / Fs.

Для примера:

- Fs = 9600 Гц → Ts ≈ 104.17 мкс;
- Nyquist frequency: fN = Fs / 2 = 4800 Гц.

Если входной сигнал имеет компоненту 6 кГц при Fs = 9.6 кГц, то он попадает в зону aliasing и будет «перекладываться» в допустимую область спектра.

Это один из главных учебных эффектов, которые проект должен показывать.

### 2.2 Теорема Котельникова–Шеннона

Сигнал ограниченной полосы B, то есть с максимальной частотой fmax, можно восстановить без потерь информации, если:

Fs > 2fmax

или, в более строгом виде:

Fs >= 2B.

Именно поэтому в проекте:

- частота дискретизации является параметром конфигурации;
- в GUI должна быть видна Nyquist frequency;
- в анализаторе спектра будет предупреждение при f > Fs/2;
- должны быть демонстрационные сигналы ниже и выше предела Найквиста.

### 2.3 DFT и FFT

Дискретное преобразование Фурье для последовательности x[n] длины N:

X[k] = Σ_{n=0}^{N-1} x[n] e^{-j 2πkn/N}

где k - номер частотного бинa, а частота соответствующего компонента вычисляется как:

f[k] = k * Fs / N

Для практики на ПК используется FFT (быстрое преобразование Фурье), которое является эффективным вариантом вычисления DFT.

Именно это преобразование позволяет:

- видеть спектр сигнала;
- выделять доминирующую частоту;
- оценивать гармоники;
- видеть искажения и leakage.

### 2.4 Оконные функции и spectral leakage

Если сигнал не содержит целого числа периодов внутри окна наблюдения, то спектр размазывается. Это явление называется spectral leakage.

Для уменьшения эффекта используются окна, например:

- прямоугольное окно;
- окно Ханна (Hann):

w[n] = 0.5 - 0.5 cos(2πn / (N-1))

Использование окон позволяет уменьшить боковые лепестки и сделать частотный анализ более «чистым».

### 2.5 Цифровые фильтры

Фильтрация в цифровом виде основана на линейной свёртке:

y[n] = Σ_{k=0}^{M-1} h[k] x[n-k]

где h[k] - импульсная характеристика фильтра.

В проекте будут использоваться:

- moving average - простейший FIR-фильтр для сглаживания;
- FIR low-pass - для отсеивания высоких частот;
- optional high-pass / band-pass для демонстрации разных режимов фильтрации;
- на ПК - реализация как на NumPy, так и на учебной reference-реализации.

### 2.6 ADC, квантование и измерение

У ATmega328P ADC 10-битный, то есть:

- 2^10 = 1024 уровня;
- шкала 0..1023;
- при эталонном напряжении Vref результат кодируется как число от 0 до 1023.

Входное напряжение для кода код можно выразить как:

V_in = (ADC_code / 1023) * Vref

Локально на Arduino это важно по двум причинам:

- ограничение по частоте дискретизации и ISR timing;
- ограничение по SRAM и скорости UART;
- искажения от квантования и шумов.

### 2.7 STFT и спектрограмма

Обычный FFT показывает усреднённый по выбранному фрагменту спектр и не указывает,
когда именно менялась частота. Для нестационарных сигналов используется коротковременное
преобразование Фурье (STFT):

```text
X[m, k] = Σ(n=0..L−1) x[n + mH] · w[n] · exp(−j·2πkn/L)
```

Здесь `L` - длина окна, `H` - шаг между соседними окнами, `w[n]` - оконная функция,
`m` - индекс кадра времени, `k` - частотный бин. Спектрограмма отображает
`|X[m,k]|` или его квадрат как цвет на плоскости «время–частота». Частотный шаг
равен `Fs/L`, временной шаг кадров - `H/Fs`. Увеличение `L` уточняет частотное
разрешение, но усредняет более длинный временной участок; уменьшение `H` делает
кадры плотнее, но увеличивает вычисления и не повышает разрешение по частоте.

В SignalScope доступны прямоугольное окно, Hann и Hamming, а также шкалы амплитуды,
мощности и dB относительно максимума. Для dB показывается настраиваемый диапазон,
значения ниже которого ограничиваются нижней границей шкалы.

### 2.8 Взаимная корреляция и задержка

Взаимная корреляция сопоставляет два сигнала при разных относительных сдвигах:

```text
r_AB[l] = Σ(n) x_A[n] · x_B[n + l]
ρ_AB[l] = r_AB[l] / (||x_A||₂ · ||x_B||₂)
```

В текущей реализации перед вычислением нормированной корреляции из каждого сигнала
вычитается его среднее. Положительный лаг означает, что сигнал B запаздывает
относительно A; оценка задержки в секундах равна `l_peak/Fs`. Это энергетическая
нормировка корреляционных сумм, а не коэффициент Пирсона и не оценка физической
скорости распространения. Во вкладке можно сдвигать воспроизводимый синтетический
мультитон либо сравнить захват Arduino с его искусственно задержанной копией.

## 3. Архитектурная идея проекта

Система строится так, чтобы каждый слой решал одну задачу и был математически прозрачным.

```
Analog signal
      ↓
ADC (ATmega328P)
      ↓
Timer-triggered sampling
      ↓
ISR / fixed SRAM buffer
      ↓
UART binary stream
      ↓
Python serial layer
      ↓
Protocol parser
      ↓
Time-domain + frequency-domain DSP
      ↓
GUI: oscilloscope, spectrum, spectrogram and correlation
```

### Firmware

Arduino firmware должен быть организован как набор модулей:

- `adc.c/h` - работа с ADC через регистры,
- `timer.c/h` - аппаратная генерация частоты дискретизации,
- `buffer.c/h` - фиксированный буфер в SRAM,
- `uart.c/h` - UART на регистрах,
- `protocol.c/h` - бинарный протокол,
- `filter.h` - интерфейс-заготовка для будущей фильтрации на AVR (текущая рабочая фильтрация выполняется в PC DSP),
- `main.c` - координация системы.

### PC part

Python-часть отвечает за:

- приём бинарного протокола через serial;
- синтаксический анализ пакетов;
- преобразование ADC к напряжению;
- вычисление измерений;
- FFT и спектральный анализ;
- фильтрацию(пока что);
- визуализацию в PySide6 + pyqtgraph.

## 4. Почему важно использовать фиксированные буферы и регистровый доступ

У ATmega328P очень ограничены:

- 2 KB SRAM;
- 32 KB Flash;
- 16 MHz CPU;
- UART bandwidth;
- ISR and timing budget.

Поэтому проект специально строится на:

- статических массивах фиксированного размера;
- отсутствии heap allocation;
- минимальных блокировках;
- максимально коротких ISR;
- аккуратной синхронизации между ADC, таймером и UART.


## 5. Главное отличие от обычного Arduino-проекта

## 9. Запуск GUI на Windows

Python-приложение запускается из PowerShell. Нужен Python 3.10 или новее:

```powershell
cd .\pc
.\install.ps1
.\run.ps1
```

`install.ps1` создаёт локальное окружение `pc\.venv` и устанавливает пакет с зависимостями. GUI запускается в окне, а не в консоли. Для запуска без виртуального окружения можно установить зависимости вручную:

```powershell
cd .\pc
py -m pip install -e .
.\run.ps1
```

В GUI доступны два источника:

- **Demo signal** - синтетические sine, square, triangle и noise. Нажмите **Start**, чтобы проверить осциллограмму, измерения, FFT, оконную функцию Hann и фильтры без Arduino.
- **Arduino** - выберите COM-порт, нажмите **Connect**, затем **Start**. Потенциометр отображает медленно меняющееся напряжение; сигнал ожидается на A0, канал и опорное напряжение можно менять в GUI.

Интерфейс отображает сигнал во временной области, односторонний спектр амплитуд, число отсчётов, среднее, RMS, Vpp, оценку доминирующей частоты и частоту Найквиста. Фильтры **Moving average** и **FIR low-pass** показаны вместе с исходным сигналом и его спектром. Для демонстрационного сигнала приложение знает частоту генератора и может явно подсветить ожидаемый alias; для реального входа уже возникший alias невозможно однозначно определить по одним дискретным отсчётам.

Дополнительно доступны вкладки **Spectrogram** (STFT с настраиваемыми размером окна,
перекрытием, типом окна и шкалой) и **Cross-correlation** (сдвиг синтетического
сигнала или задержка копии текущего захвата). Для STFT используются только полные
кадры: интерфейс сообщает, если накоплено меньше отсчётов, чем размер окна.

Сейчас прошивка захватывает один ADC-канал, а режим **Current acquisition** строит
второй сигнал цифровым сдвигом этого же массива. Это демонстрация алгоритма задержки,
не измерение расстояния или задержки звука между двумя датчиками. Аналоговый вход
не имеет микрофонного предусилителя: сырой электретный капсюль нельзя подключать
непосредственно к A0. Нужен подходящий аналоговый модуль с предусилителем и смещением;
его выход должен оставаться в диапазоне GND…Vref. Цифровой выход компаратора даёт
только логические уровни и не сохраняет амплитудную форму, необходимую для такой
спектрограммы. Аппаратные тесты с микрофоном не выполнялись.

## 10. Сборка и прошивка Arduino Uno

Для прошивки нужен пакет **Arduino AVR Boards**. Установите Arduino IDE и в Boards Manager найдите и установите **Arduino AVR Boards**. Либо, если установлен Arduino CLI, выполните один раз:

```powershell
arduino-cli core update-index
arduino-cli core install arduino:avr
```

`firmware/build.ps1` и `firmware/upload.ps1` ищут `avr-gcc`, `avr-objcopy` и `avrdude` как в `PATH`, так и в стандартной папке пакетов Arduino пользователя (`%LOCALAPPDATA%\Arduino15\packages`). Поэтому обычно вручную добавлять каталоги компилятора в PATH не нужно. Если тулчейн не найден, скрипт выводит эти инструкции явно. После установки из PowerShell в корне проекта выполните:

```powershell
.\firmware\build.ps1
.\firmware\upload.ps1 -Port COMx
```

Подставьте номер COM-порта, который Windows показывает для платы. Доступные порты можно вывести командой `.\firmware\upload.ps1 -ListPorts`; загрузка требует явного указания порта, например `.\firmware\upload.ps1 -Port COMx`. Скрипт загрузки пересобирает firmware перед записью flash, чтобы HEX соответствовал текущим исходникам. Если Windows запрещает доступ к порту, закройте SignalScope, Arduino Serial Monitor/Plotter и другие приложения, открывшие тот же COM-порт, и проверьте назначение порта в Device Manager.

Если порт виден, но avrdude пишет `cannot set com-state`, это означает, что COM-порт открылся, однако USB-UART драйвер отказался применить serial settings. Для клона Uno с CH340 проверьте **Device Manager → Ports (COM & LPT) → USB-SERIAL CH340 → Properties → Driver**: обновите/переустановите официальный WCH CH340 driver; если проблема появилась после обновления, проверьте **Roll Back Driver**. Затем отключите и подключите плату снова. Командой `mode COM5: BAUD=115200 PARITY=N DATA=8 STOP=1` можно отдельно проверить, принимает ли Windows требуемые для загрузчика параметры 115200/8-N-1 (замените COM5 на актуальный порт). `upload.ps1` распознаёт `cannot set com-state` и выводит отдельную подсказку, включая обнаруженную версию драйвера.

Для потенциометра подключите два крайних контакта к **5V** и **GND**, средний контакт (ползунок) - к **A0**. Общий провод обязателен. Не подавайте на аналоговый вход напряжение ниже GND или выше выбранного Vref. Приложение считает Vref равным 5.0 V по умолчанию; фактическое напряжение AVcc следует измерить мультиметром для точных вольтовых показаний.

Прошивка обменивается с GUI по UART 115200 baud, 8N1. Аппаратный Timer1 задаёт частоту отсчётов; ADC ISR только помещает 10-битные коды в кольцевой буфер. Основной цикл формирует пакеты до 30 отсчётов (максимум 64 байта payload) и передаёт их через UART с TX interrupt. При включённом окне доступа GUI отправляет команды Start/Stop, частоту дискретизации и канал ADC.

В GUI доступен диапазон 100–4000 отсчётов/с; рекомендуемое начальное значение - 2000 отсчётов/с. Частоту ограничивает UART: при 115200 baud и 8N1 теоретический предел линии около 11520 байт/с ещё до учёта заголовков и CRC. Каждый ADC отсчёт занимает два байта, а SRAM ATmega328P составляет всего 2 KB. Поэтому передача 9600 отсчётов/с в виде 16-битных кодов через выбранный протокол неустойчива и не используется как рабочая настройка.

## 11. Протокол пакетов и DSP-модель

Все целочисленные поля передаются little-endian. Каждый пакет имеет общий формат:

```text
SYNC (0xA5) | TYPE (u8) | LENGTH (u16) | PAYLOAD | CRC-16/CCITT (u16)
```

CRC-16/CCITT рассчитывается по sync, type, length и payload (полином `0x1021`, начальное значение `0xFFFF`). PC-парсер сохраняет неполный хвост между чтениями UART, принимает несколько пакетов одним фрагментом и повторно синхронизируется после повреждённых данных.

Для типа `0x01` (ADC block) payload устроен следующим образом:

```text
sampling_frequency_hz (u16) | sequence (u16) | sample[0] (u16) | ... | sample[n-1] (u16)
```

Каждый `sample` лежит в диапазоне 0…1023. Преобразование к напряжению:

`V[n] = ADC[n] · Vref / 1023`

Команды типа `0x06` начинаются с кода команды: `0x10` Start, `0x11` Stop, `0x12` заданная частота `u16`, `0x13` канал ADC `u8`, `0x14` запрос информации об устройстве. При открытии COM-порта Arduino Uno может автоматически перезапуститься, поэтому GUI ждёт завершения загрузки платы перед отправкой команд.

Для блока из N отсчётов частотные бины FFT располагаются с шагом:

`Δf = Fs / N`

GUI вычитает среднее значение перед FFT, чтобы убрать DC-составляющую с графика спектра; окно Hann уменьшает spectral leakage, а окно rectangular позволяет увидеть её влияние. Moving average является FIR-фильтром с коэффициентами `h[k] = 1/M`; FIR low-pass использует оконный sinc-прототип. Дискретная фильтрация реализует свёртку:

`y[n] = Σ h[k] · x[n-k]`

Текущая версия GUI предназначена для быстрой визуальной оценки живого входа и учебных DSP-экспериментов, а не для калиброванных измерений или лабораторного измерителя точности.
